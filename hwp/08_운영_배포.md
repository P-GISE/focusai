# 08. 운영 배포

FocusAI 웹앱은 Docker 멀티 스테이지 빌드와 GitLab CI, Docker Compose 기반으로 배포됩니다. 상세한 ibetter 서버 절차는 `focusai-webapp/DEPLOYMENT.md`를 우선합니다.

## 로컬 개발

```powershell
cd focusai-webapp
npm install
Copy-Item .env.example .env
Copy-Item .env.server.example .env.server
npm run db:init
npm run dev:all
```

기본 주소:

- Web: `http://127.0.0.1:5173`
- API: `http://127.0.0.1:8787`
- Health: `http://127.0.0.1:8787/api/health`
- Vite proxy health: `http://127.0.0.1:5173/api/health`
- Vite proxy bootstrap: `http://127.0.0.1:5173/api/bootstrap`
- 모바일 로컬 확인: `http://<PC_IP>:5173`

개별 실행:

```powershell
npm run dev:client
npm run dev:server
npm run dev:bot
```

프런트엔드만 켜져 있고 `dev:server`가 꺼져 있으면 로그인 화면에 `서비스 서버에 연결할 수 없습니다.`가 표시됩니다. 이 경우 `npm run dev:server`를 별도 터미널에서 실행하거나 `npm run dev:all`을 사용합니다. 서버가 나중에 켜지면 클라이언트는 약 5초 간격의 헬스체크 재시도로 `/api/bootstrap`을 다시 불러옵니다.

개발/프리뷰 클라이언트는 기본 `0.0.0.0`에 바인딩되어 같은 네트워크의 실제 휴대폰에서 접속할 수 있습니다. PC에서만 열고 싶으면 실행 전 `FOCUSAI_CLIENT_HOST=127.0.0.1`을 설정합니다.

로컬 확인:

```powershell
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:5173/api/health
Invoke-WebRequest -UseBasicParsing http://127.0.0.1:5173/api/bootstrap
```

모바일 로컬 확인:

```powershell
ipconfig
Invoke-WebRequest -UseBasicParsing http://<PC_IP>:5173/api/health
Invoke-WebRequest -UseBasicParsing http://<PC_IP>:8787/api/health
```

주의: 모바일 브라우저의 카메라 권한은 HTTPS 보안 컨텍스트가 필요합니다. 로컬 LAN HTTP에서는 UI와 API 연결까지 확인하고, 실제 카메라 권한과 트래킹 세션은 HTTPS 배포 주소에서 검증합니다.

## Android APK 빌드

Android APK는 Capacitor Android 프로젝트로 만듭니다. local APK는 웹앱을 Android 앱 안에 포함하는 embedded asset 방식이고, server APK는 운영 웹 `https://focusai.ibetter.kr`를 여는 hosted 방식입니다. Android 빌드의 기본 API 주소는 `https://focusai.ibetter.kr/api`입니다.

필수 준비:

- Android Studio 또는 Android SDK
- `ANDROID_HOME` 또는 `ANDROID_SDK_ROOT`
- Java

명령:

```powershell
npm run build:android:web
npm run android:sync
npm run android:apk
```

디버그 APK 산출물:

```text
focusai-webapp/android/app/build/outputs/apk/debug/app-debug.apk
```

현재 공유용 APK 팩:

```text
focusai-webapp/apk-packages/focusai-apk-pack.zip
focusai-webapp/apk-packages/focusai-local-debug.apk
focusai-webapp/apk-packages/focusai-server-debug.apk
```

`focusai-local-debug.apk`는 내장 웹 리소스 방식이고, `focusai-server-debug.apk`는 `CAPACITOR_SERVER_URL=https://focusai.ibetter.kr`로 운영 사이트를 직접 여는 방식입니다. 두 파일 모두 debug 서명 APK입니다.

API 주소를 바꿀 때:

```powershell
$env:VITE_ANDROID_API_BASE_URL='https://focusai.ibetter.kr/api'
npm run android:apk
```

스토어 배포 전에는 debug APK가 아니라 서명된 Android App Bundle을 준비합니다.

```powershell
npm run android:aab
```

현재 로컬 검증 상태:

- `npm run build:android:web`: 통과
- `npx cap sync android`: 통과
- `npm run android:apk`: 통과
- Local debug APK: `focusai-webapp/apk-packages/focusai-local-debug.apk`
- Server debug APK: `focusai-webapp/apk-packages/focusai-server-debug.apk`
- APK pack zip: `focusai-webapp/apk-packages/focusai-apk-pack.zip`

현재 로컬 SDK는 `D:\tmp\android-sdk`에 설치되어 있고, `android/local.properties`의 `sdk.dir`로 연결되어 있습니다. 설치된 주요 패키지는 `platforms;android-36`, `platform-tools 37.0.0`, `build-tools;36.0.0`, `build-tools;35.0.0`입니다. 다른 PC에서 `npm run android:apk` 실패 메시지가 `SDK location not found`이면 Android Studio를 설치하거나 SDK 경로를 `ANDROID_HOME`/`ANDROID_SDK_ROOT` 또는 `android/local.properties`의 `sdk.dir`로 지정합니다. 현재 작업 경로에 한글이 포함되어 있어 `android/gradle.properties`에는 `android.overridePathCheck=true`를 설정했습니다.

APK는 Android 전용입니다. iPhone은 APK 설치가 불가능하므로 추후 Xcode 기반 iOS 빌드, IPA/TestFlight, App Store 절차를 별도로 진행해야 합니다.

## Dockerfile

`Dockerfile`은 두 단계로 구성됩니다.

### build stage

- base: `node:22-bookworm`
- `npm ci`
- 전체 소스 복사
- `npm run build`

### runtime stage

- base: `node:22-bookworm-slim`
- `NODE_ENV=production`
- production dependency만 설치
- `dist`, `server/dist`, `db` 복사
- `/app/uploads` 생성
- `node` 사용자로 실행
- `EXPOSE 8787`
- `/app/uploads` 볼륨
- `/api/health` Docker healthcheck

## Docker Compose

현재 `docker-compose.yml`은 `web` 서비스 하나를 정의합니다.

주요 설정:

- container name: `focusai-ibetter-kr`
- env file: `.env.server`
- volume: `uploads:/app/uploads`
- network: external `web`
- Traefik label: `focusai.ibetter.kr`
- service port: `8787`

주의: 운영 `.env.server`는 Git에 커밋하지 않고 서버의 `/data1/docker/focusai/.env.server`에 보관합니다. 기존 서버에 `/data1/docker/focusai/.env`만 있으면 배포 스크립트가 첫 배포 시 백업해 `.env.server`로 복원하는 호환 경로를 사용합니다.

## GitLab CI

`.gitlab-ci.yml` stages:

1. `verify`
2. `deploy`

### verify

- image: `node:22-bookworm`
- `npm ci`
- `npm run lint`

push와 merge request에서 실행됩니다. 현재 CI verify는 lint 중심이며, 배포 전 로컬 필수 검증은 `npm run lint`, `npm test`, `npm run build`를 별도로 수행합니다.

### deploy_production

main 브랜치에서만 실행됩니다.

흐름:

1. `/data1/docker/focusai/.env.server`를 임시 백업
2. 기존 컨테이너 `docker compose down`
3. CI 소스를 `$DEPLOY_PATH`로 동기화
4. `.git`, `node_modules`, build artifact, `.npm` 제거
5. 운영 `.env.server` 복원
6. `docker compose build`
7. `docker compose up -d`
8. 컨테이너 상태와 최근 로그 확인

## DB 운영

운영 DB는 MariaDB입니다.

권장:

- 앱 전용 계정 사용
- root 계정 사용 금지
- 현재 MVP 운영은 `AUTO_MIGRATE_SCHEMA=true`와 앱 계정 DDL 권한을 허용한다
- 운영 규모가 커지면 배포 전 마이그레이션을 별도 절차로 실행하고 앱 런타임은 DML 권한만 갖도록 전환한다
- `db/schema.sql`은 참고용, 실제 적용은 `ensureSchema()`와 운영 절차 기준

DDL 권한 최소화 전환 절차:

1. 배포 전 점검에서 `npm run build`와 `npm test`를 통과시킨다.
2. 유지보수 시간에 운영 `.env`를 백업한다.
3. 임시 마이그레이션 계정 또는 DDL 권한이 있는 앱 계정으로 `AUTO_MIGRATE_SCHEMA=true` 상태에서 새 컨테이너를 1회 기동한다.
4. `/api/health`와 관리자 화면에서 DB 상태를 확인한다.
5. 스키마 반영이 끝나면 앱 런타임 계정에서 DDL 권한을 제거하고 `AUTO_MIGRATE_SCHEMA=false`로 전환한다.
6. 다음 배포부터는 스키마 변경이 있는 경우 3번 절차를 먼저 수행한 뒤 일반 앱 컨테이너를 기동한다.

## uploads 볼륨

`uploads` 볼륨은 단순 업로드 파일뿐 아니라 운영 상태 파일도 보관할 수 있습니다.

현재 의미 있는 파일:

- `.focusai-secrets/discord-bot-settings-secret`
- `discord-notification-settings.json`
- `lostark-discord-bot/` 작업 데이터

이 볼륨을 삭제하면 Discord 봇 토큰 복호화와 알림 채널 설정에 영향이 생길 수 있습니다.

## 백업과 복구

DB와 uploads 볼륨은 같은 시점의 한 묶음으로 백업합니다. DB만 복구하면 프로필 이미지, 첨부 파일, Discord 설정 파일, 봇 토큰 암호화 키가 맞지 않을 수 있습니다.

권장 백업 절차:

1. 배포 전 또는 정기 백업 시각을 정한다.
2. MariaDB dump를 생성한다.
3. `/data1/docker/focusai/uploads` 또는 Docker named volume의 실제 mountpoint를 압축한다.
4. `/data1/docker/focusai/.env.server`는 별도 secret 백업 저장소에 보관한다.
5. DB dump, uploads archive, `.env` 백업의 생성 시각과 대상 커밋 SHA를 기록한다.

예시:

```bash
mkdir -p /data1/backups/focusai/$(date +%Y%m%d)
cd /data1/backups/focusai/$(date +%Y%m%d)
docker exec mariadb-11.4.5 mariadb-dump -ufocusai_app -p focusai > focusai.sql
tar -C /data1/docker/focusai -czf uploads.tar.gz uploads
cp /data1/docker/focusai/.env.server env.server.backup
git -C /data1/docker/focusai rev-parse HEAD > deployed-revision.txt 2>/dev/null || true
```

복구 테스트는 별도 임시 환경에서 수행합니다.

1. 새 MariaDB 데이터베이스에 `focusai.sql`을 복원한다.
2. uploads archive를 `/app/uploads`에 해당하는 위치로 복원한다.
3. `.env.server`의 DB 접속 정보를 임시 DB로 바꾼다.
4. 컨테이너를 기동하고 `/api/health`를 확인한다.
5. 로그인, 이미지/첨부 파일 접근, Discord 설정 조회, 알림 채널 설정 파일, Lost Ark 봇 작업 데이터가 복구되었는지 확인한다.
6. `DISCORD_BOT_SETTINGS_SECRET` 또는 `.focusai-secrets/discord-bot-settings-secret`이 백업과 같은지 확인한다.

복구 테스트가 실패하면 운영 백업은 성공으로 보지 않습니다.

## Discord 봇 운영

FocusAI 봇:

- Express 서버 안에서 in-process runtime으로 실행됩니다.
- 관리자 API로 설정/시작/중지합니다.
- 서버 재시작 시 DB의 `enabled=true`이면 자동 시작합니다.

Lost Ark 봇:

- 별도 Node 하위 프로세스로 실행됩니다.
- 기본 경로는 `lostark-discord-bot`입니다.
- 운영 번들에서는 필요한 data 파일을 `uploads/lostark-discord-bot`로 seed합니다.

## 배포 후 점검

```bash
docker ps --filter name=focusai-ibetter-kr
docker logs --tail 50 focusai-ibetter-kr
docker inspect --format '{{.State.Health.Status}}' focusai-ibetter-kr
curl -I https://focusai.ibetter.kr/api/health
```

`/api/health`는 공개 헬스체크이므로 민감한 세부 정보를 반환하지 않습니다. 확인 범위는 API 프로세스 생존, MariaDB 설정 여부와 연결 가능 여부, Anthropic 사용 설정 여부입니다. SMTP와 Discord 봇 상태는 관리자 인증이 필요한 관리자 화면/API에서 확인합니다.

앱 내부 점검:

1. 회원가입/로그인
2. 관리자 계정 확인
3. 학습 세션 저장
4. 공지 등록/표시
5. 문의 접수/처리
6. AI 피드백 fallback 또는 Anthropic 호출
7. SMTP 비밀번호 재설정
8. FocusAI Discord 봇 시작과 command 등록
9. Lost Ark Discord 봇 시작
10. 모바일 브라우저에서 로그인 화면, 주요 화면 이동, API 연결 확인
11. HTTPS 모바일 브라우저에서 카메라 권한 허용과 트래킹 세션 확인

## 운영 주의사항

- 실제 `.env`와 토큰은 Git에 넣지 않습니다.
- `deploy/prod.env.example`에 실제 비밀값이 들어갔다면 즉시 교체하고 키를 폐기/재발급합니다.
- `uploads` 볼륨을 삭제하기 전 Discord bot secret 영향도를 확인합니다.
- Traefik/Cloudflared 설정은 서버 실제 상태로 별도 확인합니다.
- 운영 log에는 토큰 원문이 남지 않게 합니다.

## 시크릿 회전 절차

실제 값이 노출되었거나 담당자가 변경되었거나 정기 회전 시점이면 다음 순서로 교체합니다.

1. 교체 대상과 영향 범위를 기록한다.
2. 새 값을 발급한다.
3. `/data1/docker/focusai/.env.server`를 백업한다.
4. 운영 `.env.server`에 새 값을 반영한다.
5. `docker compose up -d --force-recreate web`로 앱 컨테이너를 재생성한다.
6. `/api/health`, 로그인, AI 피드백, SMTP 비밀번호 재설정, Discord 봇 시작을 확인한다.
7. 기존 값을 제공자 콘솔에서 폐기한다.
8. 회전 시각, 담당자, 검증 결과를 운영 기록에 남긴다.

대상별 주의점:

- `MARIADB_PASSWORD`: DB 계정 비밀번호 변경과 `.env` 변경을 같은 점검 창에서 수행한다.
- `ANTHROPIC_API_KEY`: 새 키 적용 후 AI 피드백이 성공하거나 명확한 설정 오류를 반환하는지 확인한다.
- `SMTP_PASSWORD`: SMTP 제공자의 앱 비밀번호를 새로 만들고 비밀번호 재설정 메일 발송을 확인한다.
- `DISCORD_BOT_TOKEN`: Discord 개발자 포털에서 토큰을 재발급한 뒤 관리자 화면에서 봇 토큰을 다시 저장한다.
- `DISCORD_BOT_SETTINGS_SECRET`: 이 값을 바꾸면 저장된 봇 토큰을 복호화할 수 없으므로, 변경 후 관리자 화면에서 Discord 봇 토큰을 다시 저장한다.
