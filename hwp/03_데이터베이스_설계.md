# 03. 데이터베이스 설계

FocusAI는 MariaDB를 사용합니다. 참고 DDL은 `focusai-webapp/db/schema.sql`에 있으며, 실제 런타임 스키마 보정은 `server/src/mariadb.ts`의 `ensureSchema()`가 담당합니다.

## 테이블 목록

| 테이블 | 역할 |
| --- | --- |
| `users` | 사용자 계정, 관리자 여부, 동의 정보 |
| `ai_usage_logs` | Anthropic 요청량, 예상 비용, 차단 기록 |
| `subjects` | 과목 마스터 |
| `user_subjects` | 사용자와 과목의 N:M 관계 |
| `user_settings` | 사용자별 학습/알림/화면 설정 |
| `study_sessions` | 학습 세션 요약과 메모 |
| `session_score_samples` | 세션 점수 타임라인 샘플 |
| `session_events` | 세션 중 이벤트 로그 |
| `auth_sessions` | 서버 인증 세션 토큰 해시 |
| `password_reset_tokens` | 비밀번호 재설정 토큰 해시 |
| `announcements` | 공지 |
| `support_tickets` | 문의/신고 |
| `admin_audit_logs` | 관리자 작업 감사 로그 |
| `discord_bot_settings` | FocusAI/Lost Ark Discord 봇 설정과 상태 |

## 핵심 관계

```text
users
  1:N user_settings
  N:M subjects via user_subjects
  1:N study_sessions
  1:N auth_sessions
  1:N password_reset_tokens
  1:N support_tickets
  1:N ai_usage_logs

study_sessions
  1:N session_score_samples
  1:N session_events

users
  1:N announcements.created_by / updated_by
  1:N admin_audit_logs.actor_user_id
  1:N discord_bot_settings.updated_by
```

## 주요 테이블

### `users`

주요 컬럼:

- `email`: 고유 이메일
- `password_hash`: 서버에서 해시한 비밀번호
- `display_name`
- `daily_goal_hours`
- `auth_source`
- `is_admin`
- `consent_version`
- `privacy_consent_at`
- `camera_consent_at`

관리자 접근은 DB의 `is_admin`과 환경변수 `ADMIN_EMAILS` 정책이 함께 작동합니다.

### `user_settings`

사용자별 기본 학습 설정을 저장합니다.

주요 컬럼:

- `idle_threshold_seconds`
- `focus_alert`
- `break_reminder`
- `save_raw_video`
- `default_session_minutes`
- `default_session_mode`
- `auto_resume_session`
- `sound_alerts`
- `show_live_score`
- `show_event_log`
- `reduce_motion`
- `keep_screen_awake`

### `study_sessions`

세션 요약과 결과 메모를 저장합니다.

주요 컬럼:

- `session_id`
- `user_id`
- `subject_name`
- `mode_name`
- `goal_minutes`
- `elapsed_seconds`
- `focused_seconds`
- `avg_score`
- `final_score`
- `timeline_json`
- `tab_switches`
- `idle_events`
- `absence_events`
- `hidden_seconds`
- `highest_score`
- `lowest_score`
- `studied_note`
- `distraction_note`
- `next_goal_note`
- `created_at`: 클라이언트가 보낸 세션 생성 시각
- `server_created_at`: 서버 수신 시각

서버는 비정상적으로 미래이거나 오래된 클라이언트 시각을 보정합니다.

### `auth_sessions`

브라우저 쿠키에는 원본 세션 토큰이 저장되고, DB에는 SHA-256 해시만 저장됩니다.

주요 컬럼:

- `session_token_hash`
- `user_id`
- `expires_at`
- `last_seen_at`
- `user_agent`

### `password_reset_tokens`

비밀번호 재설정 토큰도 원본 대신 해시만 DB에 저장합니다.

주요 컬럼:

- `token_hash`
- `expires_at`
- `used_at`
- `requested_ip`
- `user_agent`

### `support_tickets`

문의/신고 내역입니다.

상태:

- `open`
- `reviewing`
- `resolved`
- `closed`

카테고리:

- `inquiry`
- `bug`
- `report`
- `account`
- `other`

### `announcements`

공지 관리용 테이블입니다.

주요 컬럼:

- `title`
- `body`
- `tone`
- `is_active`
- `is_pinned`
- `starts_at`
- `ends_at`
- `created_by`
- `updated_by`

활성 공지는 `is_active`, 노출 기간, 고정 여부를 함께 고려합니다.

### `discord_bot_settings`

ID별 봇 설정을 저장합니다.

현재 의미:

- `id=1`: FocusAI 관리자 봇
- `id=2`: Lost Ark Discord 봇

주요 컬럼:

- `enabled`
- `token_ciphertext`
- `token_preview`
- `client_id`
- `guild_ids`
- `admin_channel_id`
- `admin_role_ids`
- `bot_actor_user_id`
- `register_commands`
- `admin_url`
- `support_poll_ms`
- `health_poll_ms`
- `daily_summary_hour`
- `status_state`
- `bot_user_tag`
- `last_started_at`
- `last_stopped_at`
- `last_error`

토큰 암호화 키는 `DISCORD_BOT_SETTINGS_SECRET` 또는 `uploads/.focusai-secrets/discord-bot-settings-secret`에서 옵니다.

### `ai_usage_logs`

AI 사용량과 비용 제한을 추적합니다.

주요 컬럼:

- `provider`
- `model_name`
- `request_day`
- `input_tokens`
- `output_tokens`
- `cache_creation_input_tokens`
- `cache_read_input_tokens`
- `estimated_cost_usd`
- `was_blocked`
- `blocked_reason`

## 운영 권한

운영 DB 계정은 `root` 대신 전용 계정 사용을 권장합니다. `AUTO_MIGRATE_SCHEMA=true`를 쓰려면 앱 계정에 DDL 권한이 필요합니다.

필요한 대표 권한:

- `SELECT`, `INSERT`, `UPDATE`, `DELETE`
- `CREATE`, `ALTER`, `DROP`, `INDEX`
- `CREATE TEMPORARY TABLES`
- 필요 시 `SHOW VIEW`, `TRIGGER`, `EVENT`, routine 관련 권한

`db/production-grants.sql`은 참고용이며, 실제 운영 권한은 `DEPLOYMENT.md`의 최신 절차를 우선합니다.

## 데이터 보존 주의점

- `uploads` 볼륨과 DB의 Discord 토큰 암호화 키는 함께 보존해야 합니다.
- `auth_sessions`, `password_reset_tokens`는 보안 데이터이므로 원본 토큰을 기록하지 않습니다.
- `study_sessions` 삭제는 점수 샘플과 이벤트를 cascade 삭제합니다.
- 사용자 삭제는 해당 사용자의 세션, 문의, 설정, 인증 세션을 cascade 삭제합니다.

## 데이터 보존 정책

현재 운영 정책은 “서비스 기능 데이터는 계정 삭제 시 삭제, 운영 감사 데이터는 보존 또는 익명화 검토”입니다.

권장 처리:

- 계정 삭제: 인증 세션, 사용자 설정, 과목 연결, 학습 세션, 점수 샘플, 이벤트는 삭제한다.
- 지원 문의: 사용자 본문과 첨부 파일은 개인정보로 보고 삭제 또는 익명화 대상에 포함한다.
- 감사 로그: 운영 보안 추적 목적이 있으므로 즉시 삭제하지 않고 actor 정보를 익명화하는 방향을 우선 검토한다.
- AI 분석 원문: 학습 세션 원문과 설정에서 파생되므로 계정 삭제 또는 보존 기간 만료 시 함께 삭제한다.
- AI 사용량 집계: 비용 정산과 abuse 추적을 위해 개인 식별 정보를 제거한 집계만 남긴다.
- 공지: 운영 공지는 계정 삭제와 무관하게 보존한다.
- 공지/문의 첨부 파일: 문의 첨부는 문의 정책을 따르고, 공지 첨부는 공지 종료 후 별도 보존 기간을 둔다.

보존 기간 기준:

| 데이터 | 기본 정책 | 비고 |
| --- | --- | --- |
| 인증 세션 | 만료 즉시 삭제 가능 | 원본 토큰은 저장하지 않음 |
| 비밀번호 재설정 토큰 | 만료 또는 사용 후 삭제 가능 | 원본 토큰은 저장하지 않음 |
| 학습 세션 | 사용자가 계정을 유지하는 동안 보존 | 계정 삭제 시 삭제 |
| AI 분석 입력/결과 | 학습 세션 보존 기간과 동일 | 개인정보 정책과 같은 범위로 관리 |
| 지원 문의 | 처리 종료 후 운영 정책 기간 보존 | 계정 삭제 요청 시 삭제/익명화 검토 |
| 관리자 감사 로그 | 보안 감사 기간 동안 보존 | 계정 삭제 시 actor 익명화 우선 |
| 공지 | 운영 이력으로 보존 | 첨부 파일은 별도 만료 정책 필요 |

법적 또는 고객 계약상 보존 요구가 생기면 이 표보다 해당 요구가 우선합니다.
