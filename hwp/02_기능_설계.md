# 02. 기능 설계

## 사용자 기능

### 계정과 인증

- 회원가입, 로그인, 로그아웃
- HttpOnly 세션 쿠키 기반 인증
- 세션 만료와 `auth_sessions` 기반 서버 세션 관리
- 현재 개인정보/카메라 동의 버전 수락
- 비밀번호 변경
- 이메일 기반 비밀번호 재설정
- 계정 삭제

### 프로필과 설정

사용자는 이름, 일일 목표 시간, 과목 목록, 기본 세션 설정, 알림/화면 설정을 저장할 수 있습니다.

주요 설정:

- 일일 목표 시간
- 기본 세션 시간과 기본 모드
- 유휴 판단 기준
- 집중 알림, 휴식 알림, 사운드 알림
- 자동 세션 복구
- 실시간 점수와 이벤트 로그 표시
- 화면 절전 방지
- 모션 감소
- 원본 비디오 저장 여부

### 학습 세션

학습 세션은 브라우저에서 진행되며 다음 데이터를 기록합니다.

- 과목, 모드, 목표 시간
- 경과 시간, 집중 시간
- 평균 점수, 최종 점수, 최고/최저 점수
- 점수 타임라인
- 탭 전환 수
- 유휴 이벤트 수
- 자리비움 이벤트 수
- 숨김 상태 시간
- 세션 이벤트 로그
- 세션 결과 메모

진행 중 세션은 `localStorage`에 draft로 저장되어 새로고침 후 복구할 수 있습니다.
트래킹 안정성, 기준선 상태, 판정 근거는 학습 화면에서 실시간 표시용으로 사용하며 원본 영상은 서버에 저장하지 않습니다.

### 집중도 보조 분석

`src/lib/studyVision.ts`는 MediaPipe FaceLandmarker를 사용해 순간 감지값을 만들고, `src/lib/focusTracking.ts`는 그 감지값을 시간 축에서 안정화합니다.

감지 상태:

- 얼굴 인식 가능 여부
- 얼굴 수
- 프레이밍 상태
- 집중/읽기/산만/자리비움/미지원 상태
- 머리 방향, 고개 각도, 눈 깜박임 점수
- 얼굴 중심 좌표와 화면 내 얼굴 크기 비율

트래킹 안정화:

- 세션 시작 후 약 8초 동안 개인 기준선을 수집합니다.
- 최근 샘플 창에서 얼굴 중심, 얼굴 크기, 머리 방향, 눈 감김, 문서 포커스, 유휴 시간을 함께 평가합니다.
- 짧은 고개 회전이나 순간적인 얼굴 미감지는 바로 자리비움으로 확정하지 않고 `transient`로 둡니다.
- 얼굴 미감지가 지속되거나 머리/자세 이탈이 임계 시간 이상 이어질 때만 `away` 또는 `distracted`로 확정합니다.
- 확정 자리비움 상태에서는 집중 점수를 낮게 제한하고, 안정적인 상태에서는 과도한 감점을 피합니다.

이 분석은 학습 점수 계산을 보조하고 학습 화면의 `트래킹 안정성` 카드에 안정성, 기준선 상태, 판정 근거를 표시합니다. 브라우저 지원이나 모델 로딩에 실패하면 미지원 상태로 fallback합니다.

### 리포트와 AI 피드백

- 저장된 세션을 기반으로 대시보드와 리포트를 표시합니다.
- 리포트는 `html2pdf.js`로 PDF 다운로드를 지원합니다.
- AI 피드백은 Anthropic API가 가능하면 Claude 모델을 호출하고, 실패하거나 비활성화되면 로컬 분석으로 fallback합니다.
- 일일 요청 수와 예상 비용은 `ai_usage_logs`로 관리합니다.

### 공지와 문의

- 사용자는 활성 공지와 공지 목록을 확인합니다.
- 사용자는 문의/버그/신고/계정/기타 유형으로 support ticket을 접수합니다.
- 사용자는 자신이 접수한 문의 내역을 확인합니다.

## 관리자 기능

### 관리자 대시보드

관리자는 `GET /api/admin/overview`를 통해 다음 정보를 확인합니다.

- 전체 사용자 수, 관리자 수
- 전체/오늘/최근 7일 세션 수
- 평균 집중 점수
- 최근 사용자와 최근 세션
- 사용자별 세션 통계
- 상위 과목
- 일별 통계
- 공지 목록
- 문의 목록
- 감사 로그
- 시스템 상태와 rate limit 상태

### 사용자 관리

- 사용자 관리자 권한을 변경할 수 있습니다.
- 현재 로그인 사용자 자신의 관리자 권한 제거, 마지막 관리자 제거, allowlist 관리자 변경은 차단합니다.

### 공지 관리

- 공지 등록
- 공지 제목/내용/유형/활성 여부/고정 여부/노출 기간 수정
- 공지 삭제
- 활성 공지 조회

공지 유형:

- `info`
- `good`
- `warn`
- `danger`

### 문의 처리

문의 상태:

- `open`
- `reviewing`
- `resolved`
- `closed`

관리자는 문의 상태와 관리자 답변을 저장할 수 있습니다. 변경 내역은 감사 로그에 남습니다.

### Discord 봇 관리

관리자 화면에서 FocusAI 봇과 Lost Ark 봇을 각각 설정할 수 있습니다.

공통 설정:

- Bot token
- Client ID
- Guild ID 목록
- 관리자 채널 ID
- 관리자 역할 ID 목록
- 봇 작업을 기록할 FocusAI 관리자 사용자 ID
- slash command 등록 여부
- 관리자 URL
- 문의 polling 주기
- health polling 주기
- 일일 요약 발송 시각

저장된 토큰은 `discord_bot_settings.token_ciphertext`에 암호화되어 저장됩니다.

## FocusAI Discord 봇 명령

서버 내장 FocusAI Discord 봇은 다음 명령을 등록합니다.

| 명령 | 기능 |
| --- | --- |
| `포커스상태` | MariaDB, AI, SMTP 상태 확인 |
| `포커스요약` | 관리자 운영 요약 확인 |
| `문의목록` | 최근 문의 목록과 상태 필터 |
| `문의상세` | 문의 상세와 상태 변경 버튼 표시 |
| `문의처리` | 문의 상태와 관리자 답변 변경 |
| `사용자조회` | 이름/이메일로 사용자 조회 |
| `최근세션` | 최근 학습 세션 조회 |
| `감사로그` | 최근 관리자 감사 로그 조회 |
| `공지등록` | 공지 등록 |
| `공지목록` | 최근 공지 목록 조회 |
| `공지수정` | 공지 내용/유형/고정/활성 상태 수정 |
| `공지종료` | 공지 비활성화 |
| `알림채널설정` | 현재 Discord 채널을 알림 채널로 설정 |
| `알림채널목록` | 알림 채널 설정 목록 확인 |

알림 종류는 `support`, `health`, `daily`입니다.

## Lost Ark Discord 봇

Lost Ark 봇은 FocusAI 서버에서 별도 Node 하위 프로세스로 실행됩니다. 기본 경로는 `lostark-discord-bot`이며, `LOSTARK_DISCORD_BOT_DIR`로 바꿀 수 있습니다. 서버는 봇 실행 시 Discord 토큰, Client ID, Guild ID 환경변수를 주입합니다.
