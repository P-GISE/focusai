# 관리자 권한 경계 변경

공개 가입에서 주장한 이메일만으로 관리자 권한을 얻지 못하도록 자동 이메일 승격을 제거했다.
가입은 항상 `is_admin=0`을 저장하며 로그인·기존 세션·프로필·관리자 목록은 DB 플래그만 읽는다.
기존 `is_admin=1` 데이터와 마지막 관리자/자기 권한 변경 방어는 유지한다. 스키마 변경은 없다.

## 적용 전

보호된 서버 관리 접속으로 현재 관리자의 DB 플래그와 정당한 권한 부여 이력을 확인한다.
기존 `ADMIN_EMAILS`만으로 접근하던 계정은 이 배포 후 관리자 기능을 사용할 수 없다.
해당 계정이 정당한 운영자임을 독립적으로 확인한 경우에만 정확한 기존 사용자 ID에
대한 별도 승인된 권한 부여 절차를 사용한다. 미가입 이메일·새 공개 가입자를 자동 승격하지 않는다.
계정 이메일·이름·ID·비밀번호/해시를 CI 또는 공유 문서에 출력하지 않는다.

## 검증과 복구

일반 이메일·기존 allowlist 이메일로 신규 가입해도 일반 권한이어야 한다.
이미 DB에 관리 권한이 있는 운영자는 로그인 및 세션 복원 후에도 관리자여야 한다.
실제 운영자 확인 전에 main 병합/자동배포를 진행하지 않는다. 일반 로그인과 업무 데이터는 유지한다.

앱 이미지 롤백은 DB 플래그를 변경하지 않는다. 이전 이미지로 되돌리면 이메일 기반
승격 취약점이 다시 열리므로 기능 회귀는 우선 보안 수정 버전에서 해결한다.
긴급 롤백이 불가피하면 가입/관리자 경로의 임시 차단과 영향을 별도 승인 후 적용한다.
